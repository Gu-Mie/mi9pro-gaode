# 高德直连手环的可行性（2026-09-14）

结论：**当前工程仍需要手机腕上导航作为通知转发服务，但日常不需要打开它的页面。尚未找到可在这台小米手环 9 Pro 上直接替换现有方案、并经验证可用的官方高德快应用。** 这不是对所有小米设备或未来版本的判断。

## 已核对的路径

| 路径 | 证据与判断 |
| --- | --- |
| 高德 → 运动健康 → 官方配套高德手环应用 | 手机上运动健康 3.59.0 确有 `AmapWearableConnectService` 和 `AmapConnectProvider`。只读代码显示需要设备支持第三方应用、目标应用已安装、手机和手环证书指纹一致。这条官方集成路径有实现基础，但没有取得并验证适配 9 Pro 的官方高德 RPK。 |
| 高德 → 运动健康普通通知 | 已安装运动健康会过滤高德 ID 1236 的导航通知；本机真实导航正好使用该 ID。此前仅打开普通通知同步不能解决，不应让用户反复切通知开关。 |
| 高德 → 自制手环腕上导航，删除手机配套程序 | 当前 Vela interconnect 按配套应用身份通信，并要求手机和快应用包名、签名一致。我们现有包名/签名与高德不同，不能通过改包名就接入高德通道。[小米官方说明](https://iot.mi.com/vela/quickapp/zh/features/network/interconnect.html) |
| 集成高德智能手表/硬件方案 | 高德官方公开了智能手表方案（首页列出 RTOS 支持）和硬件导航方案。这是厂商或开发者集成导航能力的入口，不能据此认定它会开放读取用户正在运行的高德 App 导航，也没有发现面向本项目的即装即用替代包。[高德开放平台](https://developer.amap.com/)、[智能手表方案](https://lbs.amap.com/solution/smartwatch)、[智能硬件方案](https://developer.amap.com/solution/smarthard) |

运动健康代码证据来自本机已经取得的 `.local/mi-health-amap-provider.txt`、`mi-health-amap-service.txt`、`mi-health-amap-filter.txt` 和 `mi-health-base-notify-service.txt`，本轮重新核对了 `isSupportThirdPartyApp`、`getFingerPrintByPackage`、`getFingerprint` 和失败分支。没有修改运动健康。

搜索到的泛用教程、其他型号体验和旧社区帖子没有提供可验证的本机官方安装包，因此没有把它们当成“9 Pro 已支持直连”的证据。公开搜索未找到也不证明该应用绝不存在；地区、账号、固件和上架情况需要在官方商店进一步核对。

## 后续可执行方向

1. 如果运动健康针对这台 9 Pro 的应用商店出现官方高德应用，先核实开发者、设备支持及安装包身份，再单独验证：关闭腕上导航转发 → 高德开始导航 → 从表盘进入指引 → 手机锁屏后持续更新。
2. 若只有高德商业 SDK，先确认是否提供手机高德导航投送协议、Vela JS 接口以及 9 Pro 适配支持；不要把“重新开发导航引擎”当成删除转发应用的小改动。
3. 目前可交付的是精简为后台配套服务的腕上导航，首次完成设置后不用在手机上手动打开它。没有 root、替换运动健康、改签名或安装来历不明的高德包。
