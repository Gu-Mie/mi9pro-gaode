## 已确认的结果

- 用户确认手环 0.1.1 的本地演示可以显示，原先打开黑屏的问题消失。
- ADB 首次检查高德主用户的 `android.permission.POST_NOTIFICATIONS` 为 `granted=false`，当时系统中没有活动的高德通知。为主用户开启权限后立即采集到导航通知。

- 手机 0.1.1 增加「直行152米」这种距离在动作之后的解析。11 项 Java 测试和 Android Lint 通过。
- 更新手机 APK 后曾出现通知权限仍在、监听服务却未连接的状态。前台恢复时加入 `requestRebind`；本机还通过 ADB 重新注册了原已授权的监听，随后确认 `listenerConnected=true`，高德通知解析为 `active`。
- SDK 记录显示：一个已连接设备、互联权限通过、手环应用已安装、消息监听注册成功、发送成功。
- 用户最终反馈：「现在手机端可以了，手环显示的是手机端内容」。据此确认本次手机到手环显示链路已通。

## 可重复使用的诊断

在工程根目录运行以下命令，只读取本应用诊断状态与高德通知。诊断日志不包含通知正文，原始高德样本仅保存在被忽略的 `.local/samples/`。

```powershell
& .local/adb/platform-tools/adb.exe shell dumpsys activity service io.github.mi9pro.navigation.NavigationNotificationListener
& .local/adb/platform-tools/adb.exe logcat -d -s WristNav:I '*:S'
.\tools\capture-amap.ps1
```

若服务尚未绑定，可在手机打开腕上导航后使用：

```powershell
& .local/adb/platform-tools/adb.exe shell dumpsys activity io.github.mi9pro.navigation
```

调试 APK 提供仅持有 Android `DUMP` 权限的调用方（如 ADB shell）能访问的测试接收器；release 变体不包含该接收器。`demo` 会向手环发送明确标注的 15 秒演示消息，之后恢复实际状态：

```powershell
& .local/adb/platform-tools/adb.exe shell am broadcast -n io.github.mi9pro.navigation/.DiagnosticReceiver --es command demo
```

## 运动健康直接同步高德的核对（2026-09-14）

通过 ADB 只读分析手机上实际安装的小米运动健康 3.59.0 APK，未修改或替换该应用。

1. 普通消息通知转发中，`NotificationFilterHelper.isMipmapNotification` 在包名为 `com.autonavi.minimap` 且通知 ID 为 `1236`（`0x4d4`）时返回 true。`BaseNotifySyncService.handleNotificationPosted` 调用它后记录过滤原因并直接返回，不继续转发。此前采集到的「直行152米 / 高德导航中」恰好符合这两个条件。因此，单纯开启高德的消息通知转发，不能绕过这条规则。
2. APK 同时包含高德专用互联服务 `AmapWearableConnectService` 与 `AmapConnectProvider`。后者连接时检查设备支持第三方应用、目标手环应用存在，并比较手机包证书与手环应用指纹；成功后通过 `sendPhoneMessage` 发消息。这说明高德有专用集成通道，不能笼统地说运动健康完全不支持高德。
3. 当前自制「腕上导航」使用自己的包名和开发签名，无法直接替代上述配套高德应用。尚未验证小米手环 9 Pro 当前能获取何种兼容的高德手环应用，也没有据此宣称专用通道在这台手环上已可用。
4. 手机实际界面为「设备 → 通知设置 → 消息通知」：总开关开启、自定义通知模式、仅锁屏通知、仅佩戴通知及接收通知自动亮屏均开启。这些是普通消息通知设置；接收时自动亮屏并不等于导航页面持续常亮。本次仅检查，没有更改这些偏好。

本机分析文件保存在被忽略的 `.local/mi-health-*.txt`。公开项目 [MiHealth_AmapFix](https://github.com/JoyElliot/MiHealth_AmapFix) 的作者也记录了相同过滤方法；本次没有安装其模块、进行 root 或降级运动健康。

当前链路是「高德通知 → 手机腕上导航通知监听 → 运动健康互联 → 手环腕上导航」。该次交接时尚未实施后台服务和自动打开；随后已恢复开发，最新实现和验证结果见下文。
