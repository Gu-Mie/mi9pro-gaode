# 手机 0.1.3：后台同步与自动打开手环

2026-09-14 实现。配套手环继续使用已安装的 0.1.2，不需要重新安装 RPK。

## 使用流程

1. 首次安装后开启通知使用权、同步开关和互联授权；高德自身也必须允许发布导航通知。
2. 点击「启用后台同步」，允许附近设备权限及通知权限。通知栏出现「腕上导航后台同步」后，可以退出手机页面。
3. 如需锁屏持续同步，使用「允许锁屏持续同步」完成 Android 电池优化设置，并在「应用省电与自启动设置」检查小米省电策略为「无限制」、自启动开启。保持运动健康与手环连接；这些设置的实际锁屏效果仍需真机验证。
4. 开启「导航开始时自动打开手环」。在高德点击开始导航，应用识别有效导航通知后尝试打开手环导航页面。
5. 手环停留在导航页面即可持续显示。主动切去表盘或其他应用后，这次导航的通知更新不会反复抢回页面。
6. 通过应用开关或通知栏「停止同步」停用后台服务。停止后释放 CPU 唤醒锁，并发送暂停状态；手环按正常规则熄屏。

## 实现

- `NavigationSyncService` 是 `connectedDevice` 前台服务，使用 `BLUETOOTH_CONNECT` 满足 Android 新版本的设备通信权限要求。蓝牙传输仍由运动健康 / XMS 完成，没有另外连接手环。
- 服务不依赖 `MainActivity` 生命周期；同步启用时等待高德导航，通知栏可停止服务。
- 真实导航有效且手环节点就绪时，通知轮询续期最多 60 秒的 `PARTIAL_WAKE_LOCK`，使 8 秒心跳不因 CPU 休眠而中断。它不点亮手机屏幕。暂停、结束、断连或监听失效时释放；更新停滞时租期自动到期。
- `SyncRestoreReceiver` 在开机完成和覆盖更新后尝试恢复用户保存的启用状态；后台启动被系统拒绝时捕获异常并提示，不能保证所有厂商系统都允许自动恢复。
- `AutoLaunchPolicy` 在新导航和已连接节点下允许调用 `launchWearApp(nodeId, "/pages/index")`。成功后本次导航不重复调用；连接延迟时可补发；失败最多 3 次、间隔至少 5 秒；调用 10 秒超时。
- 监听先进行 350 毫秒去抖。高德通知集合全部为空后，到下一次有效导航间隔至少 1 秒，或明确收到结束状态时，允许下一段导航再次自动打开。仍有通知但文字无法识别、监听暂时失效不作为结束证据；不足 1 秒的空集合间隔保留本次去重状态。通知没有可靠的路线会话标识，时间阈值仍是启发式判断。
- 结束、停用和断连会使旧异步回调失效。演示不自动打开手环。手动打开按钮保留用于排查。
- 对同一已连接节点再次授权时复用消息监听，避免 SDK 返回 `you have registered` 后把有效连接清掉。后台服务已运行且权限已恢复时，清除旧的权限提示。

## 当前限制

- 手环自动打开的 SDK 成功回调不等于屏幕确实被唤醒；本轮实际显示已另获用户确认，其他设备仍需观察验证。
- 自动打开去重状态保存在当前进程内。系统重建手机进程后，仍在进行的导航可能再次触发一次打开；没有可靠的高德路线会话标识，暂未跨进程持久化去重。
- 未验证真实重启恢复、长时间离线/断连恢复和无 USB 供电的深度 Doze。不要把短时 USB 联调扩展成这些保证。
- 手机收到手环 ACK 的路径仍未验证，`lastAckAt=0` 与此前一致。
