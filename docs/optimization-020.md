# 0.2.0 精简与耗电优化

2026-09-14。两端包名、签名和已打通的 JSON 通信方式保持兼容；手机和手环都构建为 0.2.0 / versionCode 5。本文件区分代码结果和真机结果，0.1.3 的验收不代表 0.2.0 已验收。

## 页面

- 手机首页仅状态、同步开关、设置；缺少授权或连接时才出现「完成设置」。自动打开、手环常亮和后台权限集中在设置中。
- 手机移除演示入口、原文调试区、ACK 说明和重复的操作提示；取消每秒轮询界面，改为状态变化通知界面。
- 手环保留状态、箭头、距离、指引及必要的剩余原文；移除演示、连接按钮、版本横幅和长说明。纯黑背景，必要的错误仍可见。
- 手环只删除与主指引完全相同的文字、固定的「高德导航中」标签；其他道路、路线或无法识别的文字仍保留。程序不生成演示导航数据；旧手机传来的 demo 帧仍明确标注，保持兼容。

## 减少重复工作

| 项目 | 原行为 | 0.2.0 |
| --- | --- | --- |
| 未变化的活动导航 | 通知重复触发发送，真机曾约每 3 秒一条 | 内容相同只保留约 8 秒心跳；内容变化立即发送，500 毫秒内的突发变化合并为最新内容 |
| 等待/结束/暂停 | 轮询时重复发送 | 状态变化发送一次；接收端保留终止状态，不把等待误报为过期 |
| 通知集合轮询 | 启用和关闭时都每 8 秒 | 导航期间按心跳期限补读，等待时 60 秒兜底，关闭同步后停止读取和轮询；高德通知事件仍立即触发去抖读取 |
| 手机页面 | 每秒重绘状态 | 页面可见时订阅状态变化，离开时移除订阅 |
| 手环页面 | 前台每秒 paint | 收到新消息或状态变化才刷新；一个定时器在数据 20 秒过期时清除指引，无导航/后台时无过期计时器 |
| 重复心跳的渲染 | 多数字段重复赋值 | 相同字段不重新赋值，原文列表不重建，只续期过期时间 |
| CPU 唤醒锁续期 | 每次通知检查调用 acquire | 活动导航仍持有有界的部分唤醒锁，但每约 30 秒续期一次；结束/暂停/断连仍立即释放 |
| 手环屏幕 | 导航时默认常亮 | 默认保持原体验，新增「导航时手环常亮」开关；关闭后服从手环正常息屏策略 |

没有直接去掉手机活动导航期间的唤醒锁，因为上一版已发生锁屏冻结，稳定通信优先。减少续期调用不等于减少唤醒锁持有时长。屏幕常亮本身仍会耗电，用户可关闭；不擅自调整手环全局亮度。

## 验证与测量边界

- Android：26 项测试（解析 11、自动打开 10、发送调度 5）、Lint 0 错误、APK 构建通过。
- 手环：24 项测试、RPK 构建、包内入口/布局尺寸/原生失败降级检查通过。测试包含可选常亮、隐藏页面、过期、相同心跳不重建列表及终止状态不依赖心跳。
- 固定导航每秒重复通知的 60 秒策略回放，发送 8 次；没有生成耗电百分比。手环心跳连续到达时过期定时器不执行，丢失心跳后仅执行一次。
- 两个包已推送至手机 Download 并核对 SHA-256；手机 0.2.0 已安装，手环仍为 0.1.2，等待用户解锁后更新。22:48:01 至 22:50:13 新手机进程在锁屏下持续发送真实导航，约每 8 秒一次，唤醒锁有效。新版手机 UI、新版手环画面与常亮开关尚未真机验收。
- 实际电量改善需相同路线、屏幕亮度和常亮设置、相同测试时长且无 USB 供电的对照测试；短时充电联调无法说明实际续航增加多少。
